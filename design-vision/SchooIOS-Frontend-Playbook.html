4Frontend North Star — UI Brain

"SchooIOS không phải dashboard. Nó là lưu khố sống của tiếng nói một ngôi trường — vận hành bằng sự chính xác của một thiết chế biên tập."

Điểm tựa thẩm mỹ: Typography + khoảng trống gánh cái đẹp · Màu gánh ý nghĩa · Motion gánh sự sống. Sang đến từ tiết chế, chất chữ, đường hairline — KHÔNG từ trang trí. Trục tự sự: VOICE → SIGNAL → ARCHIVE (HS cất tiếng → nhân sự xử lý → ban giám hiệu lưu giữ).

C · Decision Principles

Khi nhiều phương án, ưu tiên theo thứ tự: ① rõ ràng hơn → ② nhanh hiểu hơn → ③ ít lỗi hơn → ④ ít code hơn → ⑤ khớp contract hơn. Không tối ưu thẩm mỹ mà phá vận hành. Không "đẹp nhưng không dùng được". Mismatch với contract ⇒ contract thắng.

E · UI Success Definition (đo được)

UI "đạt" khi: clarity (hiểu màn trong <3s) · permission correctness (matrix 5 role × endpoint xanh 100%) · mobile usability (luồng HS dùng được ở 390px) · state resilience (empty/loading/error/permission đều có bản thiết kế, không trắng) · visual stability (0 layout-shift bất thường giữa các lần chụp; visual-diff trong ngưỡng) · speed (TTI trang vận hành nhanh, WebGL lazy).

7Screen Specs

Mỗi spec: vai trò · focal · nhịp · whitespace · type>color · motion · restraint/flourish · states · mobile · motif · screenshot-accept.

Login / Change-password critical

Split editorial: trái dòng serif + dấu signal thở; phải form gạch-chân. Focal = nút đỏ "Bước vào" duy nhất. Lỗi = ink-dim + dòng mono ("Không khớp."), KHÔNG đỏ. Đổi-MK-lần-đầu = serif ấm. Redirect đúng role (tin proxy). Mobile: 1 cột, form trên. Accept: 1 màu đỏ duy nhất, lề trái rộng, không box input.

Create Report — Raise a Signal core

Flow một-câu-một-màn (chuyện gì→category→location→khẩn?), prompt serif lớn, input hairline, validation từ Zod (mirror server). Flags rõ: toggle "cần xử lý ngay" → emergency:true (= studentFlagged). Đính kèm: disabled + "sắp có" (U2). Submit 201 → VOICE release-burst → mono Case ID. Mobile-native (hero). Accept: form restraint, flourish chỉ ở resolve.

Case Detail CORE — trung tâm

Header: caseCode mono + title serif + status pill + priority + (emergency edge nếu có). Thân = Spine dọc: origin(lời HS, serif) → node statusHistory/comment/audit theo thời gian. Internal note khảm --sunken+tag mono (HS không thấy). Panel hành động: chỉ transition hợp lệ (display-only), confirm modal cho status/assign/emergency, 409→reload. Metadata mono. Responsive THẬT TỐT (mobile: header→spine→actions stack). Accept: type-led, màu chỉ ở dot/status, spine rõ là xương sống.

Assignment / Workflow critical

Chỉ hiện transition hợp lệ; action quan trọng → confirm modal. Forbidden action KHÔNG render. RESOLVED→hơi thở gold; CLOSED. Reassign giữ status. Conflict 409 = dòng điềm tĩnh "Hồ sơ vừa được người khác cập nhật" + reload.

Comments / Notifications supporting

Comment thread trên Spine; public vs internal tách cấu trúc+tag mono. Notification = panel hairline, dòng đơn, dot signal chưa-đọc → tan khi đọc; điều hướng từ notification về case. read-all = sóng dot tan. Tránh clutter.

Emergency Lane critical

Visually distinct: oxblood + low-pulse + tempo sắc (cú phá luật DUY NHẤT) + tín hiệu chrome thường trực mọi trang. Action-heavy nhưng có kiểm soát; không nhầm status. Top-priority visibility. STUDENT→403 (không vào). Shock 2–3.

Dashboard / Home (role-aware) core

ADMIN: số đài-kỷ-niệm + Pulse Field hero (KHÔNG donut) + queue ledger + rail khẩn/đang-già. STAFF: "vụ của tôi" + bể nhận. STUDENT: serif "Tiếng nói của bạn rất quan trọng" + hành động đỏ + "Báo cáo của tôi" (KHÔNG chart). AUDITOR: read-only metrics. Mobile fallback rõ.

Search supporting — MVP filter

⌘K summon panel paper-raised (KHÔNG glass). MVP = filter trên /api/cases (status, isEmergency, category client-side, pagination). Highlight bằng --sunken. Text-search toàn cục = BLOCKED (U1) — hiện rõ "đang lọc theo bộ lọc", không giả vờ full-text. Không empty-blank confusion.

Audit Log supporting

Toàn mono, hairline rows, "cảm giác khắc", append-only. Filter entityType/entityId + pagination server. Traceability (actor·action·entity·timestamp·metadata). ADMIN/AUDITOR only (403 khác). Milestone = Impact moment (hiếm).

Hardening / QA surfaces supporting

Skeleton(thở) · ErrorBoundary · Empty(serif) · PermissionDenied · các test-hook surface. Debug surface chỉ dev (gated env).

9Verification Loop

Loop chuẩn cho mỗi nhóm màn hình, ≥3 vòng full-cycle cho core (Case Detail, Create Report, Dashboard):

  1. Inspect current → 2. Compare target (UI Brain) → 3. Identify deltas → 4. Modify → 5. tsc/lint/build/test → 6. Mở màn → 7. Chụp screenshot → 8. Đối chiếu UI Brain → 9. Score pass/fail → 10. Fix → 11. Lặp.
